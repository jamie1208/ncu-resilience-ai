- 功能清單（`validate_skill.py`）：
  - **檔案**：
    - 必要：`SKILL.md`、兩份 schema、`tests/cases.jsonl`、`tests/recorded/`；
    - `references/` 至少要有 1 個 .md；
    - `scripts/` 可以不放。
  - **frontmatter**：
    - `name` 只能用小寫英數字與單一連字號，不能以連字號開頭或結尾，長度 ≤ 64；
    - `name` 必須等於資料夾名稱；底線開頭的資料夾是模板，比對時去掉開頭底線（ADR-0013）；
    - `description` 為 1～1024 字元；
    - `metadata.version` 必須是加引號的 semver 字串，`metadata.schema_version` 必須是加引號的正整數字串。
  - **SKILL.md 章節**：7 個指定的二級標題都要有，而且順序正確。
  - **schemas**：
    - 必須是合法的 JSON，`$schema` 為 2020-12，並通過 `Draft202012Validator.check_schema`；
    - 輸出 schema 必須符合 strict 子集：每個物件都設 `additionalProperties: false`，`required` 列出全部屬性，不使用 `oneOf`、`allOf`、`not`、`if`、`then`、`else`；
    - 輸出 schema 要有共同欄位 `status`、`evidence_ids`、`reason`、`abstain_reason`，且 `status` 的列舉為 ok 與 abstain；
    - 輸入 schema 要有必填的 `evidence` 陣列，每份證據都要求 `evidence_id`、`source_code`、`text`。
  - **golden cases**：
    - 每行都是合法的 JSON 物件；至少 20 筆；normal、boundary、adversarial 三類都要有；dev 與 test 都要有；
    - id 不可重複，格式是 `<type>-<三位數字>`，前綴與 type 一致；
    - 欄位齊全，`input` 通過輸入 schema，`expected` 不可有輸出 schema 沒有的欄位；
    - `must_not` 至少 1 條；`op` 只能是 eq、in、contains、matches；除了 matches 之外都要有 path；in 的 value 必須是陣列；matches 的正規表示式必須有效。
  - **錄製回應**：
    - 每筆 case 都要有對應的錄製回應；
    - 欄位齊全（`case_id`、`skill_version`、`model`、`output`），`case_id` 與檔名一致，`skill_version` 等於 `metadata.version`；
    - `output` 通過輸出 schema；
    - 沒有對應 case 的多餘錄製檔也會擋下。
  - **命令列**：
    - 參數可以是單一 Skill、`skills/` 本身，或 `skills/*`（檔案略過）；
    - 結束碼：0 全部通過、1 有 Skill 未通過、2 沒有找到任何 Skill；
    - 一次列出所有錯誤，不會遇到第一個錯誤就停。

## 已知限制

1. **不檢查語意**：
   - 不檢查錄製輸出是否符合 expected／must_not、evidence_ids 是否存在於輸入、ok 與 abstain 的業務規則；
   - 前兩項屬於評測（P2-T05），業務規則屬於 Runner 驗證（P2-T04）。
2. **ruff 的範圍**：後端 ruff 設定只對 `backend/tests/**` 豁免 S101（assert），所以用後端設定檢查 `scripts/*/tests` 時，會出現 assert 與 subprocess 的警告。`scripts/governance/tests` 也有同樣的 17 個警告。CI 原本就只對 `backend/` 執行 ruff，所以我沒有加 noqa，只用 `--ignore S101,S603` 確認其他規則都通過。
3. **mypy 不在 CI 中**：CI 開發工具 job 沒有執行 mypy；本次在本機以 strict 模式確認過。
4. **strict 子集的判斷依據**：依照目前對 OpenAI Structured Outputs 的理解，要等 P2-T03 實際呼叫時確認。如果發現不符，要同時修改 skill-standard 和本工具。
5. **必須輸出共同欄位**：目前每個產品 Skill 的輸出都必須有 `status`、`evidence_ids`、`reason`、`abstain_reason`。S06 這類以數值為主的 Skill 如果不適用，要先修改 skill-standard。
