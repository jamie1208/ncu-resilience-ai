  - 覆蓋率：統計期間內每個核准來源「有成功擷取（succeeded）的台北日」÷「應擷取天數」，應擷取天數從 max(期間起日, 來源新增日) 起算；期間中才新增的來源在 note 註明「新增」、擷取缺漏列出來源與日期區間（note ≤ 300 字，超過截斷並註明另有幾項）；停用且期間內無擷取的來源不列入。
  - 分級門檻（AI 自行決定）：low：無可計算來源或合計 ratio < 0.5；full：合計 ≥ 0.95、每個來源 ≥ 0.9、期間內沒有新增來源；其餘 partial。

  - evidence：異常週期中符合該訊號的事件（排除查證為不實），輪流從各異常訊號取，最多 12 個；evidence_id 為事件 id；標題與摘要經 `mask_pii()`（沒有摘要時用標題）；source_code 為事件最早連結的來源，沒有時為 unknown。
  - 先看覆蓋率（low → insufficient_data），再看異常（無 → no_anomaly），兩者都不呼叫模型；其餘經 Skill Runner 呼叫 S09，寫入 ai_analysis_runs（event_id 為 NULL）。

## 已知限制

- manual_import（Facebook）每小時檢查資料夾，當天沒有擷取檔也算成功，覆蓋率會高估該來源。
- 覆蓋率以「當天至少一次成功擷取」為單位，不反映單日內的部分失敗。
- 截止日所在的週／月若尚未結束，件數不完整（只會少算，不會造成假突增）；views 以週期分組，截止日之後同一週期的事件也會算進去（與 P6-T03 一致）。
- 最近一次解讀查詢時以同一截止日重算輸入；若其他程式另外重新整理 views，或之後補登過去日期的事件／擷取紀錄，顯示的數字可能與當次交給 S09 的不同（目前只有本功能會重新整理 views）。
- 沒有 e2e（計畫只列後端驗證）；前端以 Vitest 涵蓋。
- live 評測（`--live`）未執行：需要真實 API，且 S09 SKILL.md 未改動。
