## 已知限制

1. **案例可能太容易**：
   - 第 1 輪就拿到 56/56，表示這套虛構案例幾乎沒有區分力，不代表真實資料也能達到 1.000；
   - 每篇只描述一件事、用詞明確，不像真實貼文那樣混雜、口語或語意含糊。
2. **還沒有用真實標記資料評測**：
   - `data/labeled/labels.jsonl` 有 111 筆人工標記，但標記檔不存內文，要評測得從資料庫取回原文；
   - 這是計畫外的範圍，見下方「需要人工決定的事項」第 2 項。
3. **tags 沒有評分**：評測只計算 category；tags 只用 must_not 檢查個資與「已核實」。建議標籤以外的自由詞會讓統計分散，例如「9級陣風」「掉落物」。
4. **評測程式不會自動建立 `tests/recorded/`**：
   - 新 Skill 第一次 `--record` 時會在寫第一份檔案時失敗，這次因此浪費約 US$0.001；
   - 問題在 `app/ai/eval/runner.py` 的 `_write_recording`（P2-T05），只差一行 `mkdir`；
   - 這不在本任務的檔案清單內，所以沒有修改，見「需要人工決定的事項」第 3 項。
5. **S02 與 S03 的判斷可能不一致**：兩者各自判斷是不是事件（S02 的 `is_event`、S03 的 `none`），P2-T13 的管線要決定以哪一個為準。
6. **模型輸出仍可能有變異**：連續 3 輪都是 56/56，CI 使用錄製回應，不受影響。
