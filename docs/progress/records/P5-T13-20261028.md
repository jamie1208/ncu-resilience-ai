- 功能清單：
  - `POST /api/v1/public/reports`：免登入，只收 `content`（10–2000 字）與 `location`（選填，最多 100 字）；只收 `application/json`、本文最多 8 KiB；拒絕其他欄位（含聯絡方式）、控制字元與雙向文字控制字元；回 202 與固定的 `{"status": "received"}`，不回顯投稿、不回傳 id，`Cache-Control: no-store`；沒有任何讀取投稿的公開端點（GET／PUT／PATCH／DELETE 回 405）。
  - 不落地 IP 與裝置資訊：收件匣 `anonymous_reports` 只有 id、內容、地點、收到時間；稽核 `anonymous_report.submit`（actor `anonymous`）只記字數與有無地點；request 日誌只有方法、路徑、狀態碼；`backend/Dockerfile` 以 `--no-access-log` 關閉 uvicorn 存取日誌。
  - 洪水投稿限速：每用戶端 10 分鐘 3 則、全站 10 分鐘 30 則，在解析內容前計數（格式錯誤也算），超過回 429 與 `Retry-After`；用戶端只以「行程隨機鹽 + 位址」的雜湊識別，只在記憶體。另外仍受公開 API 共用的每 60 秒 60 次限制。
  - 進入既有管線：`anonymous_report` Adapter 依遞增 id 從收件匣拉取，worker 每 10 分鐘派工，照一般來源標準化、去重、寫入 source_items 並排入分析（analysis_status pending）。來源代碼 `anonymous-report` 不是 `ncu-*`，查證規則不當成官方來源；公開規則不列出它的名稱、內容或網址。
  - 前端 `/report`：導覽列「匿名回報」；說明原文不公開、不記錄 IP 與裝置資訊、無法回覆、請勿填個資或指控特定人、緊急狀況撥 110／119；字數計數；送出不帶 cookie；成功清空表單，限速與格式錯誤顯示對應訊息並保留內容。只用 `@design` 既有元件，兩套設計都適用。

## 已知限制

- 限速是行程內記憶體計數：API 重啟即重置，多個 API 行程各自計算。全站上限會讓洪水期間的正常投稿也被擋。
- 經通道（P5-T15）時用戶端位址可能都是通道本身，單一用戶端限速會退化成全站共用；需在 P5-T15 改用通道提供的可信任標頭。通道或反向代理若有自己的存取日誌，也要一併關閉才能維持「不落地 IP」。
- 收件匣資料不刪除，投稿原文同時存在 `anonymous_reports` 與 `source_item_versions`（都只在管理端）；沒有保存期限。
- 管理端沒有獨立的收件匣頁面；投稿以一般來源文章的形式出現在既有的擷取與事件畫面。
- `report_url`（`http://127.0.0.1:8088/report`）只作為內部識別；網域確定後可改。
- 公開 e2e（Playwright）沒有加入回報流程；回報表單由 Vitest 元件測試覆蓋。
