- 功能清單：
  - **8 張核心資料表**（規格 §9）。主鍵一律 UUID（程式端 `uuid4`，資料庫端 `gen_random_uuid()`），時間一律 `timestamptz`：
    - `sources`：`code` 唯一，即「唯一來源代碼」，對應 source-inventory 的代碼。
    - `ingestion_runs`：索引 `(source_id, started_at)`，即「來源＋執行時間」；`counts` 為 JSONB。
    - `source_items`：部分唯一索引 `(source_id, external_id) WHERE external_id IS NOT NULL`；external_id 為空時，改以 `(source_id, url) WHERE external_id IS NULL` 替代，即「可空替代」。
    - `source_item_versions`：`unique(item_id, content_hash)`；content_hash 為 SHA-256 hex。
    - `events`：`type`、`status`、`created_at` 各有索引；`location_id` 可空。
    - `event_evidence`：複合主鍵 `(event_id, source_item_id)`。
    - `locations`：lat／lng 可空，即「位置不明可 null」。
    - `audit_logs`：actor、action、target、`request_id`、`metadata`（JSONB）、`created_at`。規格欄位 `timestamp` 對應 `created_at`；`request_id` 依 AGENTS.md「寫入操作產生 request_id 並寫入 audit_logs」加入。
  - 外鍵刪除行為：來源與原文一律 RESTRICT（provenance 不因誤刪而消失）；`event_evidence → events` 為 CASCADE；`events → locations` 為 SET NULL。
  - 約束名稱採固定命名規則（`pk_`、`uq_`、`ix_`、`fk_`），migration 與 models 一致。

## 已知限制

- **整合測試需要資料庫**：`uv run pytest` 現在包含整合測試，必須先 `make up`（或只啟動 db）。連不上時測試會失敗並提示，不會略過。測試使用獨立的 `<POSTGRES_DB>_test` 資料庫，不碰開發資料。
- **G0-2 的指令會對開發資料庫執行 `downgrade base`**，會清空所有資料表。現在沒有資料所以無妨；之後執行階段閘門時要注意，或改用測試資料庫。
- 狀態欄位（`events.status`、`ingestion_runs.status` 等）暫以字串儲存、沒有 CHECK 約束；合法值由 P0-T06 定義，之後以 migration 加上約束。
- `audit_logs` 尚未禁止 UPDATE／DELETE（trigger 屬 P0-T07）。
- health 端點尚未檢查資料庫連線。
- 使用者本機 `.env` 若仍有 `NCU_DATABASE_URL`，會被設定忽略，不影響運作，可自行刪除。
- 正式環境的映像不含 migration 檔，目前靠 compose 掛載；正式部署（P5-T06）需另外處理。
- 未建立 pgvector extension；向量欄位於 P2-T09 加入時再建立。
