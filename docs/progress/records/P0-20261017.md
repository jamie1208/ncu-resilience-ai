## 已知限制

延續到後續階段需注意的事項：

- **audit_logs 的 append-only 擋不住資料表擁有者**：應用程式與 migration 共用同一個資料庫帳號，正式環境需要角色分離（P5-T06）。
- **G0-2 的指令會清空開發資料庫**：P1 開始有資料後，重跑閘門前要先備份，或改用測試資料庫。
- **CI 不會在 GitHub 端阻擋合併**（使用者決定不開 branch protection），由 /finish 在合併前確認。
- **CI 沒有建置 Docker 映像**；`mypy tests` 暫不納入 CI（使用者決定），尚有 4 個既有錯誤。
- **health 尚未檢查 db／redis**；worker 在 P1-T07 之前無法啟動。
- **規格 §6.3 未明確處的決定**（verified 命名、查證可改判、blocked、resolved 可重開）寫在 `docs/architecture/state-machines.md`；P2-T10 的 S05 輸出必須使用 `verified`。
- **校方網站沒有明示授權**；正式導入前需取得校方書面同意（source-inventory）。
