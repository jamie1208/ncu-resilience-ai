- 功能清單：
  - `RssAdapter`：以 `@registry.register("rss")` 註冊，支援 RSS 2.0 與 Atom。
    - 用 httpx2 下載，帶專案 User-Agent（專案名稱與 repo 網址，不含個人信箱）、timeout，並以串流方式限制回應大小（預設 5 MB）。
    - feedparser 只拿到 bytes，不會自己連線。stub 的 `parse()` 只接受 bytes，型別檢查就能擋住誤傳網址。
  - 欄位對應：
    - `external_id`：取 guid／id，沒有時用 link。
    - 內文：優先用全文（`content:encoded`、Atom `content`），沒有時用摘要；只有標題時，用標題當內文。
    - `content_type`：依 feed 標示的類型判斷 html 或 plain。
    - 發布時間：優先用 published，沒有時用 updated，一律轉為 aware UTC。
  - 欄位缺漏的項目（沒有連結、非 http 連結、沒有任何文字）會略過，並記在 `last_skipped`。
  - 下列情況拋出 `LayoutChangedError`：feed 有項目但全部無效、回應不是 feed（例如改回傳 HTML 維護頁）。
  - 增量擷取：
    - cursor 是最新發布時間（ISO 8601、aware UTC）。
    - 邊界採「大於等於」，寧可重複也不漏；重複由 P1-T06 的冪等寫入處理。
    - 沒有發布時間的項目每輪都會回傳。
    - `next_cursor` 不會倒退；格式錯誤或沒有時區的 cursor 會拋出不可重試的 `AdapterError`。
  - 錯誤分類（供 P1-T07 判斷是否重試）：
    - 可重試（`SourceUnavailableError`）：5xx、408、425、429、逾時、連線失敗。
    - 不可重試（`AdapterError`）：其他 4xx、回應過大。
    - 錯誤訊息只含來源代碼與狀態碼，不含內文。
  - 設定（`SourceConfig.options`）以 pydantic 驗證：`url`（只允許 http(s)）、`timeout`（0–60 秒）、`max_bytes`（大於 0）；不接受未定義的欄位。

## 已知限制

- **目前沒有可上線的 RSS 來源**：
  - 已核准的校方來源都沒有提供 RSS，唯一找到的氣象署 RSS 使用聲明禁止「解析 RSS 製作衍生產品」，AI 建議不核准。
  - 因此本任務的 Adapter 只用 fixture 驗證，**沒有任何來源以 `rss` 類型上線**，也還沒建立 `config/sources.yaml`。
  - G1-1（至少 3 個來源上線）改由 P1-T03 HTML Adapter 與新增的 P1-T11 `cwa-alerts` 開放資料 Adapter 支撐。
- 沒有實作條件式請求（ETag／Last-Modified），每輪都會下載完整 feed；目前 feed 都很小，之後有需要再加。
- 允許跟隨重新導向，但不會檢查導向後的網域是否仍在核准範圍內。P1-T08 的來源健康檢查可以再補。
- 「每網域同時 1 個連線、間隔 ≥ 5 秒」的限速不在 Adapter 內，由排程器（P1-T07）負責。
- 沒有發布時間的項目每輪都會回傳，依賴 P1-T06 的冪等寫入去重。
