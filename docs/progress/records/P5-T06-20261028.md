## 已知限制

- **Docker Desktop「登入時自動啟動」目前是關閉的**（`settings-store.json` 的 `AutoStart: false`）；不打開的話重新開機後要手動開 Docker Desktop 服務才會恢復。這是使用者的機器設定，未代改，步驟寫在 runbook。
- 重新開機驗證以結束再打開 Docker Desktop 模擬；容器恢復機制與真正開機相同（daemon 啟動時依 restart 策略拉起），但仍建議使用者打開自動啟動後真的重開一次，照 runbook「重新開機驗證」跑。
- Docker Desktop 是使用者層級的 app，Mac 必須登入使用者後服務才會啟動；睡眠期間服務暫停。
- 驗證過程中曾短暫中斷本機服務（Docker Desktop 重啟），目前已全部恢復。
- `make down`／`make ps`／`make logs` 仍用基礎 compose 檔；因專案名稱相同可正常操作常駐模式的容器，但 `make up` 重建會失去日誌輪替（runbook 已註明長期運行用 `make up-local`）。
- 範圍外（使用者決定 2026-10-28）：資料庫角色分離、備份排程未做，建議另開任務。
