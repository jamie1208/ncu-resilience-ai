## 已知限制

- e2e 的模型回應是腳本化的，驗證的是管線、規則、狀態機、通知與畫面，不驗證真實模型的判斷品質。
- `make e2e` 需要本機 Docker（db、redis）與 `uv`；未加入 GitHub Actions（CI 需另配 PostgreSQL＋pgvector 服務）。
- 頁面 `/api` 請求以 page.route 轉到 e2e API，未經過 Vite 開發代理與 nginx 反向代理（代理由 `make smoke` 覆蓋）。
- `flags` 讀取時依目前的指控規則重算；規則修改後，舊通知的標記會跟著改變。
- `tests/e2e/*.ts` 不在 frontend 的 ESLint 範圍內（只做了 tsc 檢查）。
- A04 的 related_event 只在資料庫寫入，畫面呈現待 P4-T01／P4-T02。
- 每次執行都會清空並重建 `ncu_resilience_e2e`（只有名稱以 `_e2e` 結尾的資料庫才允許）。
