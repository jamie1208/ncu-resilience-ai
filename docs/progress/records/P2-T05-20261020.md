- 功能清單：
  - **指標**（`metrics.py`）：
    - `macro_f1`：類別為 gold 與 pred 的聯集，null 也算一類；
    - `precision_recall_f1`：指定正類；
    - `accuracy`；
    - `pairwise_precision_recall`：配對式合併指標，給 S04 的同事件合併用；
    - 無法計算時回傳 None，一律視為未達標。
  - **案例判定**（`metrics.py`）：
    - `rule_triggered` 實作 skill-standard §7 的 `must_not`：eq、in、contains（只看陣列）、matches（整份輸出的 JSON）；
    - `case_outcome` 對 expected 做部分欄位比對並套用 must_not；沒有通過驗證的輸出直接判定失敗；失敗原因只記代碼。
  - **評測流程**（`runner.py`）：
    - 錄製模式：每筆 case 用該 case 的錄製回應建立 FakeProvider；沒有錄製回應時記為 `no_recording`；
    - 實測模式：用 `create_provider` 建立 OpenAI；`--model` 可以換模型，但必須有價格；
    - 每筆都經過 P2-T04 的 `run_skill`，所以驗證、重試、abstain、費用檢查與正式執行完全一致；紀錄存在記憶體，不寫資料庫；
    - 累計費用達到 `--max-cost` 時停止，剩下的 case 記為 `skipped_budget`，報告標為 `incomplete`、不通過；
    - `--record`（必須搭配 `--live`）把有效輸出寫回 `tests/recorded/`。
  - **報告**：
    - summary：通過數、通過率、schema 合格率、可追溯率、abstain 率、失敗數、各類型的通過數、呼叫次數、token、費用、延遲；
    - 指標：值、門檻、是否通過；
    - 共用門檻：schema 合格率 ≥ 0.99、可追溯率 = 1.0（G2-2）；
    - 每筆 case 只記 id、類型、split、狀態、是否通過、失敗原因、expected 欄位與對應的預測值，不含來源內文與完整輸出；
    - `passed`：有執行的 case、沒有中斷、指標與共用門檻都達標。
  - **計算規則**：
    - 可追溯率：有通過驗證的輸出，或明確 abstain（包括 Runner 判定的 invalid_output 與 model_refusal）的比例；failed 和 no_recording 不算；
    - schema 合格率：有通過驗證的輸出的比例。
  - **報告檔名**：
    - 預設模型實測：`eval/reports/<skill>/<version>.json`；
    - 換模型：`<version>.<model>.json`；
    - 錄製模式：`<version>.recorded.json`；
    - 完整輸出：`eval/runs/<skill>/<時間>-<mode>-<model>.jsonl`。
  - **摘要**：`write_summary` 產生 `P2-summary.json`（G2-1），內容為每個 Skill 的通過、指標、費用，以及 all_passed。
  - **命令列**：
    - 參數：`--skill`（可重複；模板為 template）、`--all`（只含產品 Skill）、`--split`、`--live`、`--model`、`--max-cost`、`--record`、`--summary`、`--out-dir`、`--runs-dir`；
    - 結束碼：0 全部通過、1 有未通過、2 設定或參數錯誤（例如沒有金鑰、找不到 Skill）。
  - **golden 測試**（`backend/tests/golden/test_skills.py`）：
    - 對 `skills/` 底下每個有 SKILL.md 的資料夾（含模板）用錄製模式跑全部 case：每筆都要通過，報告的 passed 也要為 True；
    - CI 原本就執行 `uv run pytest -q`，會自動包含這個測試。

   - 「無 evidence_ids 被標 verified 的次數 = 0」（S05）、「同輸入結果重現 100%」（S06）、人工審閱（S07／S08）；

3. **評測不計入每日上限**：評測花費只記在報告，不和正式分析的每日用量合併計算。
4. **依序執行**：一筆一筆呼叫，10 筆約 30 秒；case 多時會比較慢。
5. **模板只有 10 筆 test**：實測結果只能證明流程可用，不足以評估模型品質。
