- 功能清單：
  - **`ManualImportAdapter`**：以 `@registry.register("manual_import")` 註冊，讀取來源資料夾中的 JSON 或 CSV 檔，轉成 `RawItem`。
  - **設定**：
    - `directory`（必填）：相對於 repo `data/` 的路徑（容器內為 `/data`）；
    - 絕對路徑、`..`，以及用符號連結跳出 `data/` 的資料夾都會被拒絕；
    - `max_files`：每輪最多讀幾個檔案，1–366，預設 31。
  - **檔案選擇**：
    - 只讀 `.json`、`.csv`，略過隱藏檔、`.tmp` 等其他副檔名、子資料夾與符號連結；
    - 依檔名排序；cursor 是上一輪處理到的最後一個檔名，只讀檔名更後面的檔案；
    - 沒有新檔案時 cursor 不變。
  - **格式**：JSON 有 `format_version: 1`、`source_code`、`items`；CSV 每列有 `source_code`。
    - 必填欄位：`url`、`content`、`published_at`、`fetched_at`；
    - 選填欄位：`title`、`external_id`（省略時以 `url` 代替）；
    - 內文一律 `text/plain`。
  - **個資欄位（ADR-0008）**：
    - 白名單以外的欄位一律拒絕整個檔案；
    - 發文者、互動者、聯絡方式等 21 個欄位名稱（`author`、`username`、`avatar`、`commenters`、`email` 等）會給出「含個資欄位（ADR-0008 不收）」的明確原因；
    - JSON 與 CSV 都會檢查，CSV 檢查標題列。
  - **驗證**：
    - 欄位型別採嚴格模式，例如時間不接受數字、標題不接受數字；
    - 時間必須是 ISO 8601，沒有時區時視為台北時間，再轉成 UTC（沿用 `normalize.to_utc`）；
    - `fetched_at` 不可晚於現在超過 5 分鐘，`published_at` 不可晚於 `fetched_at` 超過 5 分鐘；
    - 上限：檔案 5 MB、每檔 1,000 筆、內文 50,000 字、標題 300 字、`external_id` 255 字（資料庫欄位長度）；
    - 網址超過 255 字又沒有提供 `external_id` 時拒絕匯入；
    - 同一檔案內 `external_id` 重複時拒絕匯入；
    - 只接受 UTF-8，CSV 可以帶 BOM。
  - **錯誤處理**：
    - 任何一筆不合格就拋出 `ImportFormatError`（`AdapterError` 子類，不可重試），整輪不推進 cursor；
    - 錯誤訊息只含檔名、第幾筆與欄位名稱；Pydantic 錯誤以 `include_input=False` 轉成文字，不帶入值；
    - 不合格的檔案修好之後，下一輪會從這個檔案繼續。
  - **跨檔案去重**：同一篇出現在多個檔案時，以檔名較後面的為準，一輪只產出一筆。
  - **格式文件**：`docs/governance/manual-import-format.md` 寫明放置位置、`sources.yaml` 登記方式、檔案規則、JSON／CSV 欄位、時間、不收的欄位與錯誤處理；測試會解析文件中的 JSON 範例，確保文件與程式一致。

## 已知限制

1. **Docker 容器內讀不到 `data/`**：`infra/docker/docker-compose.yml` 目前只掛載 `config/` 和 `infra/migrations/`，worker 容器內沒有 `/data`。在本機直接執行 worker 可以運作；在 Docker 中執行會得到「資料夾不存在」的錯誤。要加上 `../../data:/data:ro` 掛載，但這不在本任務的檔案清單內（見需要人工決定的事項）。
2. **一個壞檔會擋住後面的檔案**：為了「整檔拒絕、不默默略過」，不合格的檔案在修好或移走之前，排在它後面的檔案都不會匯入。錯誤會記錄在擷取紀錄與死信表，可以從來源健康 API 看到。
3. **已匯入的檔案修改後不會重讀**：cursor 依檔名推進，要重新匯入就另存成新檔名。檔名不依時間排序的話（例如晚寫入的檔案取了較前面的名字），那個檔案會被略過；格式文件建議用 `YYYY-MM-DD.json`。
4. **網址不做正規化**：`external_id` 預設等於 `url`，同一篇貼文如果網址帶了不同的追蹤參數，會被當成兩篇。要由擷取端（P1-T13）輸出固定的 permalink。
5. **內文中的個資不在匯入時擋下**：只擋欄位名稱；內文裡的姓名、電話由後續的 PII 遮蔽處理。
6. **沒有 tags 欄位**：社團名稱等標籤要等 P1-T15 擴充 `RawItem` 後再加進格式（屆時要更新格式文件與白名單）。
7. **沒有做資料庫端到端測試**：執行計畫的驗證項目只有單元測試；寫入資料庫與重跑零重複，沿用 P1-T06 已驗證的 store。實際匯入會在 P1-T13 手動執行一次並檢查。
