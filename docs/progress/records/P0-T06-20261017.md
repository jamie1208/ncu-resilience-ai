## 已知限制

- **資料庫層尚未強制**：`events.status` 等欄位仍是字串、沒有 CHECK 約束；只有經過 `transition()` 的寫入受保護，直接寫 SQL 不受限制。建議在 P0-T07 的 migration（audit trigger）一併加上 CHECK 約束。
- 轉移表只檢查「狀態是否合法」，業務條件不在這裡判斷，由對應任務的呼叫端負責：

  - 「未核實的具體指控不得 eligible」：P3-T07 的 `alerts/policy.py`。

- 規格 S05 的 `confirmed` 統一為 `verified`：P2-T10 的 output schema 必須遵循，否則業務驗證會拒絕。
