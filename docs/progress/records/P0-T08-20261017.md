## 已知限制

- **沒有實際驗證 CI「會擋下壞掉的變更」**：三次執行中唯一的失敗是 workflow 本身的設定錯誤，沒有刻意推送會讓測試失敗的程式碼來確認。若要驗證，需要另外 push 一個暫時分支，屬於額外的對外操作，沒有做。
- **CI 不會在 GitHub 端阻擋合併**：依使用者決定不開 branch protection；改由 /finish 第 6 步在合併前確認 CI 全綠。直接手動 push main 的話，不受這個檢查保護。
- **Docker 映像建置不在 CI 中**（`make up`、`make smoke` 只在本機驗證過）；需要時可在後續任務加入。
- 本機沒有 `gh` CLI，CI 結果透過公開 API 讀取；repo 若改為私有，就需要 token 或 `gh`。
- runner 固定在 ubuntu-24.04，之後要主動升級。
