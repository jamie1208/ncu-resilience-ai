- 功能清單：
  - What-if 引擎 `ENGINE_VERSION` 1.0.0，透明規則是 `baseline × Π(1 − effect_i)`：
    - effect 是使用者給的件數降低比例假設區間 [low, high]，範圍 0–1。
    - 點估計：每項措施取區間中點。
    - 範圍：效果全取上限（最樂觀）到全取下限（最保守）。
    - 分位數 p05／p50／p95：用固定種子跑 Monte Carlo，抽 2000 次，效果在區間內均勻分布、彼此獨立。
    - 另外輸出點估計的降低比例。
  - 敏感度（給 P7-T03 的龍捲風圖）：一次只讓一項措施在區間兩端移動，其他措施固定在中點。輸出兩端件數 `at_low`／`at_high`、差值 `swing` 與排名 `rank`。
  - 效果未知：
    - 部分措施未知：這些措施排除在計算外，列在 `excluded_measure_ids`。
    - 全部未知：`status` 為 `not_estimable`，`estimate` 為 null，不產生任何百分比（A09）。
  - 成本分級：低於 5 萬為 low，低於 50 萬為 medium，其餘為 high，沒填為 unknown。只要有一項成本未知，總成本就是 unknown。
  - 可重現（G7-1）：同輸入同種子，結果完全相同。種子只影響抽樣分位數，不影響點估計與範圍。
  - S10 scenario-simulator 1.0.0：只解釋假設與限制，數字都由引擎計算。
    - 輸出 `assumptions`：每項納入計算的措施一項。
    - 輸出 `key_driver`：照抄敏感度排名第 1 的措施。
    - 輸出 `limitations`：`hypothetical_not_prediction` 一律要有。另外依規則加上 `independence_assumed`、`unknown_effects`、`cost_unknown`、`small_baseline`、`unsupported_assumption`。
    - 效果全部未知時 abstain，理由為 `not_estimable`。
    - 措施名稱與假設依據放在 `<untrusted_source>` 中。
  - 建立模擬（`app/simulations/service.py`）的流程：
    1. 引擎計算；
    2. S10 在請求內同步執行一次；
    3. 寫入 `scenario_runs`，S10 的執行紀錄以 `ai_run_id` 連到 `ai_analysis_runs`；
    4. 寫入稽核 `scenario.create`。
    - 措施代號依序指定為 m1…m10。
    - 沒給種子時用 `secrets` 產生一個並存下。
    - not_estimable 時不呼叫模型。
    - S10 失敗時仍保存引擎結果，解釋狀態記為 failed。
  - 管理端 API：

    - `GET /api/v1/admin/scenarios`：最近 50 筆，可用 event_id 篩選，需要 events:read_all。

## 已知限制

- 門檻由 AI 提出：計畫沒有給 S10 的數字門檻，三項 accuracy 比照 S07–S09 設為 0.90，`hypothetical_flagged` 是 F09 的驗收條件，設為 1.0。

- 成本分級門檻（5 萬／50 萬）是 AI 自行訂的 `EngineParams` 預設值，沒有本校預算依據。
- baseline 由使用者輸入，本任務沒有從 P6-T03 的統計自動帶入，P7-T03 的介面可以考慮預填。
- S10 在請求內同步執行，模型慢時請求要等十幾秒。目前只有使用者本人在用，所以不排進 Celery。
- 「摘要只能用引擎的數字」只有 SKILL.md 規則、對抗案例與人工抽看在把關，程式沒有逐一比對數字。
- 評測 cases 都是合成情境。
