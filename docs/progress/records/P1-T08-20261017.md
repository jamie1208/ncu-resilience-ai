- 功能清單：
  - **`GET /api/v1/admin/ingestion-runs`**：
    - 擷取執行紀錄，新到舊；
    - 可依來源代碼（`source`）和狀態（`status`）篩選；
    - **cursor 分頁**（規格 §10.1）：`limit` 1–100，預設 50；`meta.next_cursor` 為不透明字串，內容是（started_at, id），開始時間相同的紀錄也不會漏；
    - 每筆回傳 id、source_code、status、started_at、finished_at、counts。counts 只有筆數和錯誤類型，不含內文。
  - **`GET /api/v1/admin/ingestion-runs/health`**（使用者決定新增）：各來源健康狀態，`meta.window_days = 7`。
  - **健康狀態**（`compute_health`），依序判斷：
    1. `disabled`：未核准或已停用；
    2. `unknown`：還沒有結束的執行；
    3. `failing`：最近一次結束的是 failed 或 abandoned；
    4. `stale`：最近一次成功距今超過 3 個擷取間隔；
    5. `degraded`：7 天成功率低於 98%（G1-2 門檻），或有未處理的死信；
    6. `healthy`：以上皆否。
    - 另外提供：最近執行的狀態與時間、最近成功時間、連續失敗次數、窗口內次數、成功率、未處理死信數。
    - 成功率 = succeeded ÷（succeeded + failed + abandoned），skipped 和執行中不計。
  - **連續失敗自動停用**（使用者決定，來源盤點「共通擷取原則」第 2 條）：
    - 派工前檢查：最近 5 次有結果的執行（succeeded 或 failed）全部是 failed 時，把來源設為停用；
    - 寫入稽核紀錄 `sources.auto_disable`（actor 為 `service:ingestion`，metadata 只有連續失敗次數）；
    - skipped、abandoned 和執行中的紀錄不會中斷計數；
    - 修好後由管理者手動重新啟用；告警通知待 P3 的通知服務。
  - **權限與驗證**：
    - 兩個路由都需要 `ingestion_runs:read`（管理者）；
    - 依使用者決定，登入在 P3-T01 實作前**一律視為匿名**：未登入回 401 `UNAUTHORIZED`，已登入但沒有權限（例如服務帳號）回 403 `FORBIDDEN`；
    - 測試以覆寫身分依賴的方式驗證。帶任何 Authorization header 都不會通過（有測試）。
  - **`make health`**（`python -m app.ingestion.health`）：在終端機印出健康表格，時間以台北時間顯示，中文以兩格寬對齊。7 天運行期間用它觀察。
  - **API 共用元件**（之後的管理與公開 API 共用）：
    - `app/api/errors.py`：規格 §10.1 的錯誤碼（另加 METHOD_NOT_ALLOWED）和例外處理，所有錯誤都以 `{data: null, meta, error: {code, message, details?}}` 回應；
    - 參數驗證錯誤只回欄位和說明，**不回顯使用者輸入**（有測試）；
    - `app/api/responses.py`：`envelope()`，meta 可以附加分頁等欄位；
    - `app/api/pagination.py`：cursor 編碼與解碼，格式不對時回 VALIDATION_ERROR；
    - `app/api/deps.py`：`get_db_session`、`get_principal`（P3-T01 前回傳匿名）、`require_permission()`。
