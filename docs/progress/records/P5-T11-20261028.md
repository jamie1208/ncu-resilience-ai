## 已知限制

- Rate limit 是行程內計數：多個 API 行程各自計算。經通道（P5-T15）時，所有請求的連線位址可能都是通道本身，必須改用通道提供的可信任 client IP 標頭，否則全站共用一個額度。
- 同步每分鐘一次：事件被判為不實或封存後，公開端最晚約 1 分鐘才撤下，加上最多 30 秒的瀏覽器快取。使用者主動下架（P5-T14）直接改 state，公開 API 每次請求都查目前狀態，所以會立即生效。
- `sync_all()` 每次掃描全部事件；個人版的事件量沒有問題，事件數量大時需改成只掃描有變動的事件。
- 「使用者查證」以 `event.verify` 稽核判斷。如果使用者查證為 verified 後，管線（S05）自動改判再改回 verified，仍會視為使用者查證。
- 手動建立的改善措施沒有 cause_basis，名稱是否含推測內容由使用者負責（仍經指控比對與 PII 遮蔽）。
- 疑似指控規則與 PII 規則的限制沿用 P5-T10：關鍵字規則可能誤判或漏判，不辨識人名。
- P5-T13 加入 `POST /api/v1/public/reports` 時，必須調整 `test_auth.py` 只允許 GET 的規則，並更新威脅模型。
