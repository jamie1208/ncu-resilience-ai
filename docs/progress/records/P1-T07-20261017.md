- 功能清單（規格 F01「定時擷取、失敗重試、重試不重複寫入」）：
  - **Celery**：
    - Redis 為 broker，不保存任務結果，全部使用 UTC；
    - `task_acks_late` 讓 worker 當機時任務會重新投遞；
    - 單次任務的軟性時限 15 分鐘、硬性時限 20 分鐘；
    - worker 只開一個行程（`--concurrency=1`），讓每網域限速器在行程內生效。
  - **派工**（`dispatch_due_sources`，beat 每 60 秒執行一次）：
    - 選出「核准、啟用、在 `config/sources.yaml` 有連線設定」，而且距上次派工已超過 `poll_interval` 的來源；
    - 為每個到期來源建立一筆 `queued` 的 `ingestion_runs`，再把任務丟進佇列；
    - 前一次還在 queued、running 或 retrying 時不重複派工；
    - 擷取間隔以資料庫 `sources.poll_interval` 為準，沒有時用設定檔，再沒有就用 1 小時；
    - 前一次執行超過 2 小時還沒結束（例如 worker 當機）：標記為 `abandoned`，然後重新派工，晚到的 worker 也不會再執行它。
  - **執行**（`ingest_source` → `run_attempt`）：
    - Adapter 擷取 → 標準化（P1-T05）→ 冪等寫入（P1-T06）。
    - 推進 `sources.cursor`、標記 `succeeded` 和寫入資料在**同一個交易**；失敗時 cursor 不會前進。
    - `counts` 記錄 received、new_items、changed_items、unchanged、skipped（Adapter 略過）、invalid（標準化失敗）、attempts。
    - 同一個任務被重複投遞時，已結束的執行不會再擷取。
    - 排隊期間來源被停用或改為暫緩：標記 `skipped`，不擷取。
  - **重試與死信**：
    - 可重試的錯誤（`SourceUnavailableError`：逾時、5xx、429）標記 `retrying`，Celery 依 **60、120、240 秒指數退避**重試，最多 3 次。
    - 重試用盡，或錯誤不可重試（版型改變、4xx、其他例外）：
      - 執行標記為 `failed`；
      - 寫入 `ingestion_dead_letters`，含錯誤類型、訊息、嘗試次數、當時的 cursor；
      - 寫入一筆稽核紀錄 `ingestion.dead_letter`。
    - 錯誤訊息：Adapter 錯誤只含來源代碼和狀態碼，可以保存；其他例外可能夾帶原文，**只記類型，不記訊息**。
