## 已知限制

1. **無法追溯到單篇貼文**（ADR-0011）：
   - `url` 是社團首頁，G1-4 抽樣時要排除 facebook；
   - 內文前 300 字被修改時，會變成新的一筆。
2. **發文時間只精確到小時**：頁面只顯示相對時間，這次的 3 篇剛好是擷取時間減去整數小時。超過 1 天的貼文只顯示「1 天前」，擷取端不收；每天執行一次時不會因此漏掉，但漏跑那天的貼文會漏掉。
3. **內文已經被擷取端改過**：聯絡方式被刪掉，所以存下的不是逐字原文。
4. **計畫中的手動觸發指令不存在**：execution-plan 的 `python -m app.worker.tasks.ingest --source all --once` 並沒有實作。這次的匯入是 beat 自動派工完成的，重跑驗證則直接呼叫 `store_items`。P1-T10 需要手動觸發時，要先補上這個指令，或修正計畫。
5. **舊 worker 讀新設定失敗**：`config/sources.yaml` 是從 repo 直接掛載的。P1-T15 改成 `{url, tag}` 格式後，`make up` 之前的舊 worker 讀不懂新格式，`ncu-aa` 有一筆 22:15 的 `ValidationError` 失敗紀錄。重新建置之後的 worker 已經支援這個格式，下一輪會恢復；P1-T10 開始前要確認。之後修改設定格式時，要同時重新建置 worker。
6. **安裝腳本在 macOS bash 3.2 的問題**：第一次安裝時，`$TARGET` 後面接全形括號，被當成變數名稱的一部分，`set -u` 因此報錯。排程檔已經寫入，但腳本中斷了。已經把變數全部改成 `${...}` 的寫法，重新安裝成功。
7. **背景模式第一次自動執行還沒驗證**：明天 08:00 是第一次由 launchd 執行，要確認 `Edit(data/raw/facebook/**)` 在排程環境也能寫檔，並檢查 `logs/capture.log`。
8. **帳號風險**：每天一次、只讀，但仍然無法保證 Meta 不會把它判定為自動化行為（ADR-0008）。

## 回退步驟

1. `scripts/facebook/install_schedule.sh uninstall` 移除排程；
2. 把 sources 表的 `facebook` 設為停用，或從 `config/sources.yaml` 移除；
3. `git revert` 本任務的 commit。worker 的 `/data` 掛載會一起移除，需要重新執行 `make up`；
4. `data/raw/facebook/` 的擷取檔與資料庫中的 3 筆 facebook 項目可以保留，或刪除（刪除前需使用者同意）。
