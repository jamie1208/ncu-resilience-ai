- 功能清單（規格 F02：時間標準化、內容雜湊、語系）：
  - **時間**：
    - `to_utc()`：一律轉成 aware UTC；沒有時區的時間視為台北時間（+08:00，台灣沒有日光節約時間）。
    - `parse_datetime()`：把文字日期解析成 aware UTC，供人工匯入（P1-T04）等文字日期使用。
      - 支援西元年（`-`、`/`、`.`、`年月日`）、民國年（`115/10/17`、`民國115年10月17日`、`中華民國 115 年 1 月 5 日`）、ISO 8601（含 `Z`）。
      - 支援上午／下午（含 12 點的特殊情形）、`2時30分`、全形數字與符號。
      - 只有日期時視為台北時間 00:00。
      - 無效的日期或時間（2 月 30 日、25 點、下午 13 點、民國 0 年、缺年份）回傳 None，不猜測。
  - **文字清洗** `clean_text()`：
    - 依序做：NFC 正規化 → 全形英數與符號轉半形 → 全形空白、不換行空白轉一般空白 → 移除零寬字元與控制字元 → 每行空白收斂並去頭尾 → 3 行以上空行收斂成 1 行。
    - 全形字的處理：`ＡＢＣ１２３％＠` 轉半形；中文常用的全形標點 `！（），：；？` 保留，中文排版不受影響。
    - 重複執行結果不變（idempotent）。
  - **HTML 轉文字** `html_to_text()`：
    - 區塊元素（p、div、li、tr、h1–h6 等）以空行分段，`<br>` 換行，表格儲存格以空白分隔；
    - 略過 script、style、註解，HTML 實體會解碼；`<pre>` 保留原本的換行。
  - **語系** `detect_language()`：比較漢字數和英文單字數，較多者勝，結果為 `zh` 或 `en`；假名或韓文較多、或無法判斷（例如只有數字）時為 `und`。不新增依賴。
  - **內容雜湊**：`content_hash = sha256(normalized_text)`，UTF-8，hex 64 字元，對應 `source_item_versions.content_hash`。
  - **`normalize_item(RawItem) -> NormalizedItem`**：
    - `normalized_text` = 清洗後的標題 + 空行 + 清洗後的內文。內文和標題相同時只保留一份（Adapter 在沒有內文時會以標題當內文）。
    - 內文清洗後是空的時，只用標題；兩者都空時拋出 ValueError。
    - `NormalizedItem` 不可修改，docstring 註明 `text` 仍是不可信輸入。
- 雜湊行為（決定何時產生新版本）：
  - **相同雜湊**：只有排版、空白、換行符號、零寬字元或全半形不同，或 HTML 與純文字呈現同樣內容。
  - **不同雜湊**：內文或標題的實際內容改變。
- 新增／修改檔案：只有任務列出的兩個檔案，加上 `docs/progress/state.yaml`（P1-T05 → in_progress）和本紀錄。

## 已知限制

- **語系不存進資料庫**（使用者決定）：規格 §9 的資料表沒有語系欄位，只出現在 `NormalizedItem`；之後需要時從 `normalized_text` 重新計算。
- **標題沒有獨立欄位**：資料表也沒有 title 欄位，所以標題併入 `normalized_text` 第一段。好處是改標題也會產生新版本；反查時標題就是第一段。
- 語系判斷只是字元統計，中英夾雜且數量接近時可能判錯；不區分繁體與簡體。
- `parse_datetime` 只解析第一個找到的日期，文字中有多個日期時以第一個為準；不支援英文月份名稱（例如 Oct 17）。
- `normalize_item` 不做網址正規化，`url` 照 Adapter 提供的保存；去重依賴 P1-T06 的 `(source_id, external_id)` 唯一鍵。
