# ADR-0010：補齊已核准的處室來源（新增 P1-T16）

- 狀態：已採納
- 日期：2026-10-18

## 背景

1. P0-T09 核准了總務處（`ncu-oga-news`）、電算中心（`ncu-cc`）、圖書館（`ncu-lib`）、環安中心（`ncu-epsc`）與生輔組（`ncu-osa-life`）。但盤點時記下「列表網址在 P1 確認」，到現在都還沒有登記在 `config/sources.yaml`，也沒有在擷取。
2. 總務處是停水、停電、施工的主要來源，電算中心是網路與系統中斷的來源，環安中心負責實驗室與化學品安全，生輔組負責宿舍與校安。少了這些來源，設施類事件會大量漏失，標記樣本的類別也會更不平衡（ADR-0009 影響第 3 點）。
3. 2026-10-18 各請求一次查看：
   - `www.cc.ncu.edu.tw` 是 RPage 系統；
   - `https://www.oga.ncu.edu.tw/news` 被導向 `/error`，網站已改版，網址要重新確認；
   - 依盤點的技術備註，圖書館、環安中心、生輔組是各自獨立的系統。

## 決策

1. 新增任務 **P1-T16「處室來源補齊（總務處、電算中心、圖書館、環安中心、生輔組）」**（使用者同意，2026-10-18）。
2. 依賴 P1-T03 與 P1-T14：新的 HTML Adapter 一律沿用 P1-T14 抽出的共用 HTTP 模組，不再複製 robots 檢查與錯誤分類。
3. 範圍：
   - RPage 版型的網站登記為 `rpage` 類型，只改 `config/sources.yaml`；
   - 其他版型的網站各自寫一個 Adapter，附頁面快照與測試；
   - 開工時先逐一確認列表網址與版型，再列出確定的檔案清單；
   - 擷取頻率依盤點建議：總務處每 30 分鐘，其他每 60 分鐘。
4. 網址若跟盤點登記的不同，在 `docs/governance/source-inventory.md` 更新並註明日期；網域或 robots 規則有變動時，請使用者重新核准。
5. **P1-T10 依賴 P1-T16**：一晚穩定運行報告要涵蓋這些來源。
6. 任務總數 61 → 62。

## 實作時的調整（2026-10-18，P1-T16）

1. **總務處暫緩**（使用者決定）：網站改版為 Nuxt 前端程式，頁面本身沒有內容，消息只能經未公開的 JSON API（`POST /api/document/v0/list`）取得。這跟盤點核准的「HTML 公告頁」存取方式不同；使用者決定先暫緩，來源盤點改為「暫緩」。
2. **電算中心以 `rpage` 登記 9 個分類**：公告由 AJAX 模組載入，程式取不到列表網址；使用者在瀏覽器找到 `403-1033-15-1.php` 後，確認模組 14–22 對應 9 個分類列表（行政公告、系統維護、宿舍網路、資安訊息、授權軟體、虛擬桌面、徵才公告、最新消息、課程／活動），依使用者要求全部擷取。不需要新的 Adapter。
3. **新增共用模組**（使用者同意）：
   - `app/ingestion/html.py`：`first`、`clean`、`find_date`、`taipei_midnight`、`TAIPEI`，兩個既有 Adapter 也改用它；
   - `app/ingestion/adapters/list_detail.py`：列表＋內頁型 Adapter 的基底類別，三個新 Adapter 共用。既有的兩個 Adapter 這次不改用它。
4. 上線：`ncu-cc`、`ncu-epsc`、`ncu-lib`、`ncu-osa-life`。既有測試 `test_repo_registers_rpage_sources` 的預期集合經使用者同意加上 `ncu-cc`（仍為完全比對）。環安中心的文章編號是 hex 字串，cursor 改用「最新列表日期｜當日已擷取的編號」。

## 考慮過的替代方案

- **等 P1-T10 跑完再補**：穩定運行報告就不會涵蓋這些來源，之後還要再跑一次。
- **只補總務處和電算中心**：這兩個最重要，但圖書館、環安中心、生輔組都已核准，一起做可以只開一次任務、只確認一次版型。

## 影響

- 擷取請求量增加 5 個網域，每個網域各自限速，整體仍然很低。
- 不是 RPage 的網站，每個都會多一份要維護的解析程式；版型變動時，會由 `LayoutChangedError` 和來源健康 API 提醒。
