# ADR-0021：移除離線評測閘門，AI 語氣以示範頁第一版為準

- 狀態：已採納（使用者 2026-11-11 決定，並同意刪除與修改下方列出的既有測試）
- 日期：2026-11-11
- 決定者：使用者本人（拿掉離線評測與語氣測試、保留執行時安全驗證、語氣以示範頁第一版為準）；實作細節由 AI 決定並記錄於此
- 部分取代：
  - AGENTS.md 規則 2 中「評測門檻」不得放寬的部分（一般測試仍不得刪除、跳過或放寬）
  - AGENTS.md「SKILL.md 改動後必須重跑評測並升版本」改為「只需升版本」
  - `docs/plan/execution-plan.md`「Skill 開發標準循環」第 6、7 步與「Skill 完成定義」中的評測要求改為選做
  - ADR-0018 決策 3-4（AI 內容改語氣後要重錄、重跑評測）
  - `docs/governance/tone-guide.md` 中由 AI 在 P8-T10 訂下、比示範頁第一版更保守的規則（禁止「驚傳」這類說法、整段最多一個驚嘆號）
- 不變：執行時的安全驗證（JSON Schema、列舉與範圍、`evidence_id` 存在、逐字證據、PII 遮蔽、社群說法不寫成已確認、未查證標籤）；公開規則引擎；數值由程式計算；緊急資訊與查證標籤維持平實；不用表情符號

## 背景

1. 使用者 2026-11-05 看過示範頁（`https://claude.ai/artifact/8GiBG9iTzh8b9MK6xPgKaV`）後決定採用第一版（`Main.dc.html`），快報文字例如「宿舍區車棚又傳失竊！藍色腳踏車昨晚不見了」「後門停車場驚傳「照後鏡小偷」」「中正圖前的腳踏車，借個書回來就消失了」。
2. P8-T10 寫的語氣指南與 P8-T11、P8-T17 改的 S02／S12 SKILL.md 比第一版保守：禁止「驚傳」類字眼、限制驚嘆號，範例只取第一版最平淡的一句。正式資料中 S02 1.3.0 的輸出（例如「巷底有人在住家門口抽菸，造成二手煙困擾」）偏新聞稿口吻，使用者認為和當初設定不一樣。
3. 離線評測（`eval/thresholds.yaml` 的準確度門檻、golden cases 逐筆比對）與 `test_skill_tone.py` 不量語氣是否像播報員，只要求改 SKILL.md 後重錄、重跑 live 評測。使用者決定「AI 給什麼就用什麼」，選擇拿掉這一層、保留執行時的安全驗證。

## 決策

### 1. 移除離線評測閘門（使用者決定）

1. 刪除 `backend/tests/unit/ai/test_skill_tone.py`（版本、重錄、live 報告、播報欄位字眼的檢查）。
2. `backend/tests/golden/test_skills.py` 不再要求每筆答對與指標達門檻，只保留錄製回應的 `schema_pass_rate` 與 `traceability` 兩個全域閘門（輸出合 schema 或明確 abstain、事實性結論可追溯）。這兩項屬執行時安全驗證的範圍。
3. SKILL.md 改動後只需升版本；重錄 `tests/recorded/` 與跑 `run_eval.py` 改為選做。
4. 評測工具（`scripts/eval/`、`app/ai/eval/`）、`eval/thresholds.yaml` 與歷史報告保留，供想抽查時手動使用；後台 SkillsDashboard 照常顯示既有報告。已通過的閘門 G2-1～G2-4、G8-2、G8-5 保留為歷史紀錄，之後的 Skill 改動不需再過這些門檻。

### 2. 語氣以示範頁第一版為準（使用者決定）

1. `docs/governance/tone-guide.md` 的範例改用第一版的快報文字；允許「又傳」「驚傳」這類播報用語與標題中的一個驚嘆號；仍不得誇大事實（數字照實、不寫證據沒有的事）、不用表情符號。
2. S02 `title`、`summary.text` 與 S12 `title`、`reason`、`measures[].action` 以第一版的寫法為範例：標題有畫面、帶情緒；摘要先講經過、再補狀況、最後給一句實用提醒。
3. 安全規則不變：不寫人名、店名與個資；社群說法寫成「有同學反映」；不推測原因、不評論責任；推測帶「可能」「疑似」；緊急資訊平實。
4. 件數不由 AI 寫（第一版摘要中的「本月第 3 起」）：快報卡片與事件頁已由程式顯示「XX 系列 · 第 N 起」（P8-T06）。
5. S02 升 1.4.0、S12 升 1.3.0。`scripts/skills/validate_skill.py` 仍要求錄製回應的版本與 SKILL.md 相同，使用者選擇保留這項檢查、以新版本重錄 `tests/recorded/`（重錄時順帶產生的評測報告只是紀錄，不是閘門）；既有內容以 `rerun_tone`（P8-T17）重跑，執行前需使用者同意並先備份。

## 後果

- 改 SKILL.md 不再有自動化檢查擋下日期、地點、分類等抽取準確度的退步；退步只能從後台或公開網站看出來。
- 升版後仍要重錄（靜態驗證的版本檢查保留），每次約 US$0.06～0.10；重錄結果只需合 schema 與可追溯，不需逐筆答對。
- 語氣是否符合第一版沒有自動檢查，由使用者看實際輸出判斷。
- 第一版的標題用語（「驚傳」、驚嘆號）較有情緒，套在未查證的社群貼文上時，可能讓讀者覺得事情比實際嚴重；公開頁的「尚未查證」標籤與一鍵下架照常提供。
