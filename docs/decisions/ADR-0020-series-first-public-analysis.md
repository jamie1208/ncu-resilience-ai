# ADR-0020：以系列為分析單位、公開推測的規律與原因、快報式首頁

- 狀態：已採納（使用者 2026-11-05 同意，並同意 P8-T06、P8-T13 列出的既有測試依本 ADR 修改）
- 日期：2026-11-05
- 決定者：使用者本人（公開規律與原因、取消單一事件小報告、第 1 起就建立分析頁、首頁依類別分區的橫向滑動快報卡片、公告用播報員語氣且每則內容不同、點卡片先看公告全文、類別用圖示與配色、沿用 Minimalist Modern、匿名回報與校園韌性頁改成白話）；實作細節由 AI 決定並記錄於此
- 部分取代：
  - AGENTS.md「推測原因（S07 `hypothesized`）不公開」的硬性邊界（見決策 2）
  - ADR-0018 決策 1-1「2 件即成立」、1-3「剩不到 2 件時系列自動解散」、1-5「規律與共同原因一律只在後台」、1-9「推測原因只在後台」、2-5 第 2 點
  - ADR-0015 決策 3 第 3 點（推測原因不公開）
  - ADR-0017 的確認對象由單一事件小報告的原因改為系列分析的原因（決策 3-4）
  - ADR-0019 的 S14 輸入由單一事件小報告的 S08 措施改為系列的改善建議（決策 6）
- 不變：公開與否仍由公開規則引擎（P5-T10）的確定性規則判斷；PII 遮蔽；Facebook 只公開 AI 摘要、匿名投稿原文永不公開；未查證內容一律帶「尚未查證」標籤；一鍵下架；計數由程式計算；通知只給使用者本人；管理端不對外（ADR-0015）；設計系統沿用 Minimalist Modern 為預設（ADR-0014）

## 背景

1. 使用者在 2026-11-05 以示範頁（`https://claude.ai/artifact/8GiBG9iTzh8b9MK6xPgKaV`，第一版）說明想要的公開網站：每件事發生時都有一則快報；同類型的事件（例如腳踏車失竊）共用一份分析頁，新的一起加入時分析跟著更新，包含過往與近期事件的分析與改善追蹤；每則快報都能點到它所屬的分析頁；首頁像滑照片一樣，同類別放在同一區。
2. 現有系統以單一事件為分析單位（P4-T09 小報告：S07 原因、S08 措施），ADR-0018 再加上系列層級的分析（S12），兩層並存。使用者決定只保留系列一層：「不是每個事件都有個別的分析報告」。
3. 現有硬性邊界規定推測原因不公開；ADR-0018 也把規律與推測原因限定在後台。使用者看過「規律與原因都公開有把推測當事實散布的風險」的說明後，仍選擇公開兩者，並標示「推測，尚未查證」。

## 決策

### 1. 每個事件都屬於一個系列（使用者決定）

1. 事件建立時一律屬於一個系列：S11 判斷與既有系列同主題就加入，否則建立只有它一件的新系列。第 1 起就有分析頁。
2. 頁面上 1 件的系列顯示為「單一事件」，2 件以上才顯示「XX 系列 · 第 N 起」。
3. 拆出的事件與因改判 false 被移出的事件，各自成為 1 件的系列；件數為 0 的系列刪除。取代 ADR-0018「剩不到 2 件自動解散」。
4. 規律仍需至少 2 件子事件支持（ADR-0018 1-5 的驗證不變）；1 件時規律區塊顯示「要至少 2 起才會找規律」，趨勢圖顯示「目前只有 1 起」。
5. 手動合併的兩筆紀錄只算 1 件（P8-T01、ADR-0018 1-4 不變）。

### 2. 公開系列分析頁含規律與可能原因（使用者決定，修改硬性邊界）

1. 公開的系列分析頁包含：總覽、累計件數與最近一起、每週件數（突增由程式判斷）、發生地點分組、AI 看到的規律、可能原因、改善建議（同學／學校／相關單位）、改善追蹤、改善前後比較、這個系列的每一起。
2. 規律與可能原因一律帶「推測，尚未查證」標籤；經人工確認（ADR-0017，決策 3-4）的原因改標「已確認」。
3. **新的硬性邊界**（寫在程式裡、設定無法關閉；AI 決定，使用者確認）：
   - 規律與可能原因可以提到特定個人、群體、店家或單位（使用者 2026-11-05 決定不設限制）；這類內容由既有的指控比對（確定性規則）標記，比照 ADR-0018 2-2 的疑似指控處理：照樣公開、帶「推測，尚未查證」標籤，公開時立即在通知中心提醒使用者並附一鍵下架；
   - 引用的子事件 id 必須屬於該系列、逐字證據必須出現在該事件的證據中，否則整項丟棄（ADR-0018 1-5 不變）；
   - 「x 件中有 y 件」由程式依引用的子事件 id 計算，模型不寫數字（不變）；
   - 公開內容一律經 PII 遮蔽；
   - 可能原因第一次公開，或內容改變時，通知中心提醒使用者並附一鍵下架；提到特定個人、群體、店家或單位的，提醒中特別註明。
4. AGENTS.md 的對應句改為：「推測原因與規律只能出現在系列分析頁，且一律帶『推測，尚未查證』標籤；首次公開或內容改變時必定在通知中心提醒使用者並附一鍵下架，提到特定個人、群體、店家或單位的比照疑似指控處理。」G5-5 的定義同步修改。

### 3. 取消單一事件小報告（使用者決定）

1. 不再產生單一事件的小報告（P4-T09 的 S07、S08 呼叫與 `report_hook`）。原因、措施、改善建議只由系列分析（S12）產生。
2. S07 root-cause-analyzer、S08 solution-generator 停用：檔案保留在 `skills/` 作為歷史，Skill Runner 的管線不再呼叫，評測報告保留，不再升版（AI 決定）。S12 輸出補上原因的 `to_verify`（要怎麼查證）與改善建議的 `audience`、`horizon`、`priority`，承接 S07、S08 的欄位。
3. 既有資料：`event_reports` 保留唯讀，後台事件頁顯示「舊版事件小報告（已停用）」；不刪資料、不寫 downgrade 會遺失資料的 migration。
4. 改善追蹤與原因確認改到系列層級：
   - `response_actions` 以系列為主（ADR-0018 1-8 已規劃）；既有事件層級的措施以 migration 掛到該事件所屬的系列，原本的 event_id 保留供回溯；
   - 人工確認原因（ADR-0017）改為確認系列分析中的原因；確認依據、稽核 `report.cause_decide` 的欄位沿用，新增 `series.cause_decide`；舊的確認紀錄保留唯讀；
   - 公開規則改為依系列分析判斷改善建議與原因是否公開。
5. 公開的事件頁（快報全文）只有：標題、時間、地點、AI 摘要、查證標籤、「這是 XX 系列的第 N 起」與「看這系列的分析」。不再有單一事件的影響、原因、措施區塊。
6. 既有測試：P4-T09、P7-T07 與公開事件頁小報告相關的測試，依本決策修改或改為驗證「已停用」（需使用者同意，範圍見計畫 P8-T13）。已通過的閘門（G4-5 等）保留為歷史紀錄，不重跑。

### 4. 公開首頁：依類別分區的滑動快報卡片（使用者決定）

1. 首頁依事件類別分區（S03 類別），每區一列卡片，可以左右滑（scroll-snap），每張卡片是一則快報，新到舊。
2. 卡片：類別圖示與配色、查證標籤（文字＋框線樣式，不只靠顏色）、時間與地點、播報員語氣的標題與摘要、「XX 系列 · 第 N 起」或「單一事件」。
3. 點卡片先看快報全文，再由「看這系列的分析」進入系列分析頁；系列分析頁中標出剛剛看的那一則。
4. 每則快報的標題與摘要都依該事件的內容寫，不使用系列共用的文案（S02 的摘要，P8-T11 改播報員語氣）。
5. 首頁底部放「校園韌性成績單」與「匿名回報」入口；快報全文頁放「你也遇到類似的事？匿名告訴我們」。
6. 設計沿用 Minimalist Modern（使用者在三版示範中選第一版）；Playful Geometric 維持可切換，不改版。

### 5. 匿名回報與校園韌性頁改成白話（使用者決定）

1. 用一般人看得懂的說法，例如：「看到怪怪的事？匿名跟我們說」「這裡不是報案管道」「學校遇到狀況時，處理得好不好？」；韌性四個構面改成四個問題：「出事後，多快有人知道？」「知道之後，多快開始處理？」「開始處理後，多久恢復正常？」「同樣的事，有沒有一再發生？」。
2. 分數規則不變（P6-T05：四項各占四分之一、任一項樣本不足就不算總分、錨點是本專題自訂的目標）；只改說明文字，並明寫「幾天算好是本專題自己訂的目標，不是學校的官方標準」。
3. 緊急資訊（110／119）與「尚未查證」維持平實措辭（ADR-0018 3-2 不變）。
4. 併入 P8-T10（介面文案）；回報碼與查進度沿用 P8-T08。

### 6. ADR-0019 的調整（AI 建議，待使用者在 ADR-0019 定案時確認）

S14 的輸入改為系列分析的改善建議與系列的件數基準；入口改在後台的系列分析頁。其餘依 ADR-0019。

## 影響

- **風險：推測被當成事實**。以標籤、引用驗證、首次公開提醒與一鍵下架控制；仍可能有讀者忽略標籤，使用者已知悉。
- **風險：妨害名譽**。AI 推測的原因可能點名特定個人、店家或單位，而且公開前沒有人工把關；使用者 2026-11-05 知悉後仍決定不設限制，以標籤、通知中心提醒與一鍵下架控制（同 ADR-0018 2-2）。
- **風險：誤歸系列**。1 件就建系列後，S11 判斷錯誤會把不相干的事件放進同一頁；以後台拆出（ADR-0018 1-2）與稽核控制。
- **成本**：每個事件都會觸發一次系列分析；仍受每系列每天最多一次與每日費用上限限制。
- **既有功能**：P4-T09、P7-T07 的單一事件流程停用；資料保留唯讀。
- **規格書**：寫進 v1.2（P8-T12）。
