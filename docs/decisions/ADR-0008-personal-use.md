# ADR-0008：專案改為個人使用；Facebook 社團納入來源（新增 P1-T13、P1-T14、P1-T15）

- 狀態：已採納
- 日期：2026-10-18

## 背景

1. 原規格把系統定位為「研究專題，非校方官方系統」，但仍設計了對外功能：公開網站與 API、匿名通報、自動發布公開提醒（`AUTO_PUBLISH_ENABLED`）、多角色權限、正式部署與負載測試。這些功能需要大量安全措施（P3-T06、P3-T09），而且正式導入前都要取得校方同意。
2. 使用者決定這個系統只給自己使用，不提供給學校，也不對外公開（2026-10-18）。
3. 使用者已加入 NCU 相關的 Facebook 社團，希望把社團內容納入來源。P0-T09 盤點時，facebook 因為「沒有合法的機器存取管道」被列為待決定。Meta 已在 2024 年移除 Graph API 的 Groups API，第三方程式無法用 API 讀取社團貼文。
4. Meta 服務條款禁止未經授權的自動化擷取，這跟用途無關。改成個人使用，不會降低帳號被停用的風險。
5. P1-T12 驗收時發現 `ncu_news.py` 與 `ncu_announcements.py` 有重複的 robots 檢查與 HTTP 讀取程式，使用者同意抽成共用模組（2026-10-18）。

## 決策

1. **專案定位改為個人使用**：只有使用者本人一個使用者，不提供公開網站、公開 API 或任何對外發布管道。
2. **刪除對外功能**（使用者決定，2026-10-18）：
   - 刪除任務：P3-T02 公開 API、P3-T04 公開前端、P3-T06 匿名通報、P3-T09 發布對抗測試集、P5-T07 負載測試。
   - 刪除閘門：G3-1 未核實具體指控錯誤公開 0 次（已經沒有公開管道）、G5-3 公開事件列表 p95 < 1.5 秒。
   - 任務與閘門 ID 不重新編號，也不重複使用，避免既有程式註解與紀錄的對照失效。
3. **簡化的任務**：
   - P3-T01：改為單一使用者登入。保留 argon2、HttpOnly Cookie session、CSRF；P0-T07 已完成的 RBAC 保留，不回頭拆除，但移除匿名投稿者與公開閱讀相關的角色和權限。
   - P3-T03：吸收原本 P3-T02 的共用部分（`app/api/pagination.py`、`app/api/errors.py`、dashboard 統計）。
   - P3-T05：管理前端成為唯一的前端；移除 P0-T03 建立的 `frontend/src/public/` 骨架與「回公開網站」連結。
   - P3-T07：發布規則引擎改為「個人通知規則」，決定哪些事件要通知使用者本人。保留 PII 遮蔽與「未核實的具體指控不得呈現為已核實」的規則，因為 Facebook 貼文可能含有指控或個資。移除 `.env.example` 的 `AUTO_PUBLISH_ENABLED`。
   - P3-T08：警示改為只遞送給使用者本人（管理介面通知中心，Email 留介面），冪等規則不變。
   - P3-T10：附錄 A 的 A01–A08 依個人版改寫期望結果（例如 A05 改為社群貼文惡意誣指個人，期望是通知不呈現指控、管理端標記異常）。
   - P4-T06：CRI「公開報告」改為管理端報告頁。
   - P5-T06：正式部署設定改為「本機常駐運行」，不再需要使用者決定正式上線。
   - 閘門 G3-3「公開／管理資料隔離」改為「未登入無法存取任何事件資料」。
4. **facebook 來源核准**（使用者決定，2026-10-18）：
   - 擷取方式：每天一次，由 Claude Code 透過 Claude in Chrome 在使用者已登入的 Chrome 中讀取社團頁面。只讀不互動，不按讚、不留言、不加入或退出社團。
   - 後端不保存 Facebook 帳號、密碼或 cookie；Celery worker 不直接連線 Facebook。
   - 擷取結果依 P1-T04 的人工匯入格式輸出 JSON 到 `data/raw/facebook/`（不進 git），再經 `manual_import` Adapter 進入既有的標準化、冪等寫入與分析流程。
   - 不保存發文者姓名、帳號、頭像與留言者資訊；只保存貼文時間、內文、貼文網址與擷取時間。
5. 新增任務 **P1-T13「Facebook 社團每日擷取」**，依賴 P1-T04。
6. 新增任務 **P1-T14「HTML Adapter 共用 HTTP 模組」**，依賴 P1-T12：把 robots 檢查、串流讀取與錯誤分類移到 `app/ingestion/http.py`，`ncu_announcements.py` 與 `ncu_news.py` 改為共用，既有測試不修改。
7. **修改 AGENTS.md 規則 4**：`.claude/skills/` 放開發與資料擷取作業用的 skill（例如 P1-T13 的 `ncu-fb-capture`）；Skill Runner 仍然只載入 `skills/`，產品 Skills 與 Claude Code skills 依然分離。
8. **來源分類標籤寫入資料庫**（使用者決定，2026-10-18）：新增任務 **P1-T15「來源分類標籤寫入資料庫」**，依賴 P1-T12。`RawItem` 新增 `tags`，`source_items` 新增 `tags` 欄位（文字陣列，預設空陣列），同一篇再次擷取時取聯集。`ncu-news` 的焦點新聞、學術新聞標籤，以及 P1-T13 的社團名稱，都經這個欄位保存。AI 原本建議不寫入（S03 會自行分類），使用者選擇保留來源標籤，供之後過濾與統計使用。
9. 計畫變更：`docs/progress/phases.yaml` 刪除與新增任務並執行 `sync`，`state.yaml` 移除已刪除任務與閘門的 pending 項目；任務總數 63 → 61，閘門 26 → 24。

## 考慮過的替代方案

- **保留架構，只關閉對外功能**：改動最少，但 P3 仍要實作匿名通報與發布對抗測試，個人使用用不到，工作量大。
- **後端 Playwright Adapter 定時擷取 Facebook**：整合度最高，但擷取頻率高、容易被偵測，而且要在後端保存登入 cookie，等同保存密碼。
- **Facebook 只靠手動複製貼上**：完全沒有帳號風險，但使用者希望每天自動執行。

## 影響

- 任務 63 → 61、閘門 26 → 24；P3 目標改為「個人版最小端到端」。
- 已完成的 P0 程式中還有對外功能的殘留：`frontend/src/public/`、`.env.example` 的 `AUTO_PUBLISH_ENABLED`、`app/core/security.py` 的匿名投稿者角色，以及 `docs/architecture/rbac.md` 的公開端點。這些分別在 P3-T05、P3-T07、P3-T01 清理，本次只改文件。
- 規格書 v1.0 的公開與通報相關章節不再適用，P5-T09 的 v1.1 差異清單要記錄這次變更。
- Facebook 擷取依賴使用者電腦開機、Chrome 已登入，以及 Claude Code 背景模式能連上 Claude in Chrome；第一項驗證在 P1-T13 實測。如果背景模式無法連線，備案是每天 8:00 發出提醒，由使用者手動觸發。
- 帳號風險仍然存在。每天一次的頻率接近一般瀏覽，但無法保證 Meta 不會判定為自動化行為。
- 社團成員的貼文會存在本機資料庫，並送到 OpenAI 分析。依 AGENTS.md，日誌不得包含原文與個資，資料庫只存在本機。
