# ADR-0015：改為對外公開；重新規劃 P4–P7（事件小報告、追蹤到底、公開網站）

- 狀態：已採納
- 日期：2026-10-27
- 決定者：使用者本人（定位、公開範圍、自動公開邊界、部署方式、階段順序）；實作細節由 AI 決定並記錄於此
- 部分取代：ADR-0008 決策 1、2（不對外公開、刪除對外功能）與 facebook 核准條件第 6 點；ADR-0008 其餘決策（單一管理者、Facebook 擷取方式、來源標籤）不變

## 背景

1. 使用者以大眾版簡報（《NCU Resilience AI｜校園小幫手大眾版》）重新說明專題目標：主動收集 → 發現事件 → 判斷輕重 → 提醒 → 提出建議 → 持續追蹤，並有「給所有人的網站」（最新動態、安全提醒、事件分類查詢、改善進度、匿名回報入口）與「校園韌性成績單」。
2. G3-5 展示時發現兩個缺口：
   - 事件頁沒有「事件小報告」：events 表沒有摘要欄位；S07 root-cause-analyst 與 S08 solution-planner 已在 P2-T12 完成並通過評測，但分析管線只執行 S01–S06，API 與前端都沒有接上，計畫中也沒有任何任務負責接上。
   - 主資料庫在 P1–P3 完成後仍是 0 個事件，真實資料的端到端路徑沒有被證明可用。
3. 使用者決定（2026-10-27）：系統改為對外公開；用途是專題展示，期限 3 個月以上；展示以真實資料為主；下一個階段的 MVP 必須包含事件小報告與追蹤到底。

## 決策

1. **對外公開**（使用者決定）：新增公開網站與公開唯讀 API。管理端仍只有使用者本人一個帳號。
2. **公開內容**（使用者決定）：已查證的事件與安全提醒、事件小報告（公開版）、改善進度、匿名回報入口。
3. **自動公開，但有硬性邊界**（使用者決定）：公開與否由確定性程式判斷，不需要使用者逐筆核可，也不由模型決定。下列邊界寫成程式規則與測試，不能由設定關閉：
   - 沒有經官方來源證實（或使用者在後台查證為 true）的事件，只公開中性措辭的安全提醒，沿用 P3-T07 的中性模板，不公開事件內容；
   - 疑似指控（P3-T07 的指控規則命中）永不自動公開，只留在後台等使用者判斷；
   - S07 的推測原因（`hypothesized`）不公開，公開版小報告只放影響與建議；
   - 使用者可以在後台一鍵下架任何公開內容，下架即時生效並寫入稽核紀錄。
4. **通知**（使用者決定）：通知仍然只送給使用者本人。小報告依 S08 的 `responsible_unit` 顯示「建議轉給哪個單位」，由使用者自己決定是否聯絡；系統不寄信給任何處室。
5. **Facebook 內容**（使用者決定）：公開頁只可以顯示 AI 改寫的摘要，不顯示原文、不附連結，也不保存或顯示發文者資訊。摘要同樣適用 PII 遮蔽與指控規則。擷取方式（只讀不互動、每天一次）不變。
6. **部署**（使用者決定）：在使用者的電腦上運行，經通道（例如 Cloudflare Tunnel）對外。
   - AI 決定：通道只轉送公開網站與 `/api/v1/public/*`；管理端（`/admin`、`/api/v1/admin/*`、登入）只綁定 127.0.0.1，不經通道對外。電腦關機時公開網站停止服務，頁面不另外做離線版。
7. **站台身分**（使用者決定）：每一頁都標明「個人專題，非國立中央大學官方系統」，並放緊急聯絡方式（校安中心、110、119）。
8. **匿名回報**（AI 決定，依規格與 AGENTS.md 的不可信來源規則）：不保存 IP 與裝置資訊；只做速率限制所需的短期雜湊；投稿以 `<untrusted_source>` 進入既有管線，是另一個來源，不會因為投稿而直接公開；投稿原文永不公開。
9. **階段重排**（使用者決定）：先做後台的事件小報告與追蹤，再做公開網站，之後才是關聯／成績單與 What-if。
   - P4「真實資料、事件小報告與追蹤到底」
   - P5「公開網站與上線」
   - P6「把點連成線與韌性成績單」（原 P4 的關聯、趨勢、CRI）
   - P7「What-if 模擬與收尾」（原 P5 的 S09、S10、可攜性、規格書更新）
10. **G3-5**（使用者決定）：依原定義（個人後台 MVP），以附錄 A 的案例資料展示後通過；真實資料的展示移到 P4 的 G4-8。
11. **任務 ID**（依 ADR-0008 的不重複使用原則，AI 決定）：搬到其他階段的任務一律刪除舊 ID、以新階段的 ID 重建；同一階段內內容不變的任務保留原 ID。

    | P4-T06 | P6-T05 | 韌性成績單（CRI），增加公開版 |

12. **AGENTS.md** 隨之修改：專案定位、「系統不對外發布」的規則改為本 ADR 的公開邊界；「新增任何對外公開的端點前必須取得使用者明確同意」保留，每個公開端點在 P5-T11 列出並由使用者在 G5-8 確認。

## 考慮過的替代方案

- **維持個人使用**：風險最低，但不符合簡報「給所有人的網站」的目標。
- **只做本機展示用的公開頁（假設案例）**：沒有對外風險，但使用者希望真的上線並以真實資料展示。
- **每筆公開都由使用者人工核可**：最安全，但使用者選擇自動公開；改以第 3 點的硬性邊界控制風險。
- **系統自動寄信給負責處室**：使用者不是校方，信件可能被當成垃圾信，誤報也會直接影響處室；改為只建議轉給誰。

## 影響與風險

- **法律責任**：網站公開後，內容的妨害名譽、個資法責任由使用者承擔。第 3 點的邊界、下架功能與 G5-5（疑似指控與推測原因不出現在公開端）是主要的防線；G5-8 上線前由使用者本人確認威脅模型與公開端點清單。
- **Facebook**：公開社團貼文的摘要，比只在本機分析多了一層曝光；Meta 條款風險與帳號風險仍由使用者承擔。`docs/governance/source-inventory.md` 的核准條件同步更新。
- **校名使用**：網站使用「NCU」名稱但不是校方系統，靠第 7 點的聲明避免誤認；若校方要求，需要改名或下線。
- **可用性**：服務隨使用者電腦開關機；公開網站不保證持續可用。
- **工作量**：P5 是全新的公開端（API、前端、匿名回報、威脅模型），而且 P3-T11 的雙設計系統規則仍然適用，公開前端的每個新元件都要在兩套設計各實作一次。
- **ADR-0008 的殘留清理**：P3 已移除 `frontend/src/public/` 與匿名投稿角色；P5 重新加入時依本 ADR 的邊界設計，不還原舊程式。
- 規格書 v1.0 的公開章節重新部分適用，P7-T05 的 v1.1 差異清單要同時記錄 ADR-0008 與本 ADR。
