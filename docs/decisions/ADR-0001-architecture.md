# ADR-0001：初始架構

- 狀態：已採納
- 日期：2026-10-17

## 背景

單人開發、全程由 AI coding agent 實作，目標是先完成可展示的研究專題，並保留日後在中央大學正式導入的可能。需求見規格書 v1.0 §3、§17。

## 決策

1. **模組化單體**：FastAPI 單一後端，按 `ingestion`、`ai`、`risk`、`alerts` 等模組切分；不採微服務。待資料品質與 Skills 可靠性驗證、或正式合作需要獨立擴容時再拆分。
2. **PostgreSQL + pgvector**：關聯資料、版本、稽核與向量檢索同一資料庫，以交易確保匯入去重與 provenance 一致。
3. **Celery + Redis**：擷取、分析、通知等背景工作，支援重試與死信。
4. **Agent Skills 格式的產品 Skills + 自建 Skill Runner**：AI 能力以可攜的 Skill 封裝，Runner 負責載入、提示組裝、輸出驗證與紀錄；模型經 Adapter 存取，OpenAI 優先、可替換。
5. **規則優先的決策層**：查證狀態、風險加權、發布資格由確定性程式與設定檔決定，模型只提供分項判斷與解釋。
6. **開發輔助與產品 Skills 分離**：`.claude/skills/` 給開發用，`skills/` 給系統用。
7. **品質閘門推進**：以執行計畫的閘門而非日期推進；進度由 ncu-resilience-tracker 追蹤。

## 考慮過的替代方案

- **微服務**：部署與除錯成本過高，單人開發無法維護；模組邊界清楚後仍可拆分。
- **獨立向量資料庫（如 Qdrant）**：多一個服務與一致性問題；pgvector 在研究規模下足夠。
- **現成 Agent 框架（如 LangChain）**：抽象層較厚、版本變動快，不利於輸出驗證與評測的完全掌控；改以自建精簡 Runner。

## 影響

- 單一部署單位，P0 即可用 Docker Compose 重建完整環境。
- 模組邊界需靠目錄與測試維持；跨模組呼叫應經公開介面。
- 更換模型供應商只需新增 Provider 與調整設定。
