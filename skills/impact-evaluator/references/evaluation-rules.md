# 評估準則（S14 impact-evaluator）

## 涵蓋原因

一個原因算**涵蓋**（`covered_causes`），只要符合下列任一項：

1. 至少一項被選的建議 `cause_id` 指向它（含 investigate 查證類：查證也是在處理這個原因）；
2. 被選的一般建議（`cause_id` 為 null）內容明確在處理這個原因描述的環節（例如原因是「照明不足」，建議是「加裝路燈」）。

其他原因都放進 `uncovered_causes`。只是同類別、同地點、或籠統的「加強宣導」「多加注意」，不算涵蓋特定原因。兩邊合起來必須剛好是輸入的全部原因。

## 改善百分比區間

先依被選建議的組合決定區間的大致位置，再依下面的調整因素修正。整數，`low` ≤ `high`，最高 80。

| 被選建議的組合 | 大致區間 |
| --- | --- |
| 只有查證（investigate）或只有提醒同學注意 | 0–15 |
| 有因應（respond），沒有預防（prevent） | 5–25 |
| 有預防，涵蓋部分原因或部分子事件 | 10–40 |
| 有預防，涵蓋全部原因與大部分子事件 | 25–60 |
| 預防＋因應，涵蓋全部原因、原因已確認、追蹤已在處理或已改善 | 最高到 80 |

調整因素：

- 原因只是推測（hypothesized）：措施可能沒打中，區間往下、放寬；
- 原因已確認（confirmed）且被涵蓋：可以往上；
- 長期（long）或需要經費、其他單位配合的建議：短期內效果有限，往下；
- 追蹤狀態 `handling`／`recovered`／`improved`：已經在做，可以往上一點；`dropped`：已放棄，視為沒有效果；
- 只靠同學自律（`students`）：效果難維持，往下；
- 歷史件數少於 5 或 `baseline` 為 null：區間至少寬 20 個百分點，並在 `risks` 說明「件數少，估計不穩定」；
- 多項建議處理同一個環節：效果不能直接相加，列入 `overlaps`，區間不因此往上。

## 改善前／後情境

- `before`：現況。依子事件摘要與件數的走勢描述「多常、在哪、可能為什麼」，不寫數字。
- `after`：採用所選建議之後「可能」的樣子；與區間一致（區間低就不要寫得像問題會消失），未涵蓋的原因或地點要點出來。
