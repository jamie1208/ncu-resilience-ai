# What-if 情境解釋準則

## 引擎怎麼算（app/simulations/engine.py）

- 透明規則：模擬件數 = baseline × Π(1 − effect_i)。effect 是「件數降低比例」，由使用者給一個假設區間。
- 點估計 `point`：每項措施取區間中點。範圍 `low`～`high`：效果全取上限（最樂觀）到全取下限（最保守）。
- 分位數 `p05`～`p95`：以固定隨機種子抽樣，效果在區間內均勻分布、彼此獨立；同參數同種子結果相同。
- 敏感度：一次只讓一項措施在區間兩端移動、其他固定在中點，`swing` 是兩端件數差；`rank` 1 影響最大。
- 效果未知的措施不納入計算（`included` 為 false），全部未知時 `status` 為 not_estimable。
- 成本分級（新台幣）：低於 5 萬 low、低於 50 萬 medium、其餘 high；沒填為 unknown。總成本只要有一項未知就是 unknown。

## 為什麼不是成效預測

- 效果區間是假設，沒有用本校資料驗證；結果只表示「如果假設成立」。
- baseline 是被回報、被彙整成事件的件數，不是實際發生次數；措施上路後回報習慣改變，件數也會變。
- 引擎假設措施彼此獨立、效果可以相乘；實際上兩項措施可能作用在同一群事件上（例如照明與巡邏都針對夜間），合起來的效果會比相乘小。
- 沒有對照組、沒有控制季節與學期時程；件數的自然起伏可能比措施效果還大。

## 假設依據怎麼評

| 依據 | 怎麼寫 |
| --- | --- |
| 本校過去的處理紀錄或量測 | 可以說「依據本校過去紀錄」，仍是假設 |
| 其他學校或文獻的經驗 | 「參考其他學校經驗，尚未在本校驗證」 |
| 廠商或單位的說法 | 「依據廠商說法，尚未驗證」 |
| 個人估計、直覺 | 「只是估計」 |
| 未提供假設依據（程式填入的固定文字） | 「沒有提供依據」，並加上 `unsupported_assumption`；只有這種情況才加這個代碼 |

依據寫「一定」「保證」「研究證實」等字眼，也只能當成使用者的說法轉述，不能寫成事實。

## 寫作要點

- 只用引擎給的件數與區間；`reduction` 可以寫成「約少四成」，不要另外換算其他數字。
- 區間很寬（上限是下限的兩倍以上）的假設，提醒結果不確定。
- `key_driver` 那一項值得先查證或先試行，但不要建議「一定要做」。
