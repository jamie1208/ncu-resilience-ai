# 同事件與相關事件的判斷規則（S04）

依據人工標記的判準（`data/labeling/guidelines.md` 第 5 節；使用者 2026-10-18 決定，ADR-0009；規格 §8.1），本檔是 S04 的細化；與標記規範衝突時，以標記規範為準。

## 三種關係

| 關係 | 意義 | 例子 |
| --- | --- | --- |
| `same_event` | 兩者描述的是**同一件事** | 同一次停電的預告、延長、恢復通知；同一台被偷的腳踏車的原文與轉貼；社群貼文說「聽說科五下週三停電」與官方的科五停電公告 |
| `related_event` | 時間、地點或類型相近，但**無法確定**是同一件事 | 同一週不同宿舍的兩起失竊；同一棟建築的預定停電與另一天的突然跳電；同一天兩棟宿舍各自的停水公告 |
| `none` | 只是同一類，時間、地點與事情都對不上 | 總圖閉館與工五停電；強風特報與地震報告 |

## same_event 的條件

類別相同，地點是同一棟建築或同一區域（地點別名視為相同：工一＝工程一館、管院＝管理學院、科五＝科學五館），而且符合以下任一條件：

1. **官方公告**：公告的影響期間有重疊。例如同一次停電的預告、延長、恢復通知。
   - 公告明確寫出「調整」「延期」「改期」「延長」「恢復」「更正」先前公告的事情（同一地點、同一件工程或服務）時，即使新的時段和原本的時段不重疊，也是 `same_event`：這是同一件事改了時間。
2. **社群或其他來源**：發生時間相差 48 小時以內，而且描述的是同一件事，例如同一台車、同一次警報、同一頓餐點。
3. **社群貼文對應官方公告**：貼文描述的時間與地點落在公告的範圍內，例如「收到冒充計中的信」對應計中的釣魚信警示、「半夜宿舍在晃」對應同一時段的地震報告。

## 判斷時要注意

- **細節對不上就不是 same_event**：交通工具不同（腳踏車與機車）、地點不同（男七舍與男九舍）、原因不同（預定檢修與突然跳電）、日期相差太多，最多是 `related_event`。
- **時間要看事件本身**，不是文章的發布時間。預告文章可能比事件早好幾天。
- **追蹤、更新、澄清、轉貼**都是 same_event，即使內容補充了新的細節。對同一件事的討論、指認或補充（例如「那件事聽說是誰做的」「我也遇到了」）也算追蹤。
- **「又」「第二次」**：貼文明確說是另一次發生（「這週第二次」「今天又」），就是另一件事 → `related_event`。
- **related_event 必須是同一種事情**：兩邊都是失竊、都是停電停水、都是車禍、都是釣魚詐騙、都是腹瀉、都是火警，只是無法確定是同一次。類別相同但屬於不同的現象或措施（閉館與停電、道路管制與班次調整、系統設定錯誤造成的資料外洩與釣魚信、強風與地震、考試異動與停課、溺水與火警）→ `none`。
- **一般性的提醒、宣導，對上具體個案**：官方公告只是一般性的提醒（例如「近期流感病例增加」「近期詐騙頻傳」），沒有提到這個個案的地點或細節 → `related_event`，不是 `same_event`。公告描述的是某一次具體的事情，而貼文的細節（寄件者假冒誰、手法、時段、地點）都對得上時，才是 `same_event`，例如計中警示的那一波釣魚信。
- `article`、`candidate` 的類別、日期、地點摘要來自前面的模型輸出，可能有誤；與原文不一致時，以原文為準。
